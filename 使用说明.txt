# HCL 设备启动失败：排查记录与启动助手

## 本次问题和结果

本次电脑使用 HCL 5.7.1、VirtualBox 6.1.50 和 Windows 11。排查时发现了两个独立问题：

1. 完美世界竞技平台的 `MessageTransfer` 驱动运行时，一个不带磁盘和网卡的 VirtualBox 诊断虚拟机启动失败，日志出现 `supR3HardenedWinReSpawn`、`Error -104` 和 `Error relaunching VirtualBox VM process: 5`。临时停止该驱动后，诊断虚拟机成功启动；随后已恢复驱动。
2. HCL 使用的 Python COM 接口缓存由旧版 VirtualBox 生成，升级 VirtualBox 后没有更新，导致创建设备时出现接口参数错误。保留旧缓存并让 HCL 重新生成后，设备能够创建。

处理后，HCL 中的 S6850 设备虚拟机成功运行，使用者确认设备控制台出现命令行提示符。上述结果来自这一台电脑；其他电脑即使显示类似报错，原因也可能不同，不能保证本方法一定适用。

本包中的启动助手是为分享而调整的独立版本，支持尝试定位不同电脑上的 HCL。在原电脑上，分享版已实测能打开 HCL，关闭后驱动恢复；随后对取消授权和启动超时的处理作了代码调整，这些异常分支尚未实测，其他电脑的兼容性也需自行验证。它不是 HCL 官方软件，也不会自动修复接口缓存。

## 一、先确认和备份

1. 保存并关闭 HCL、正在使用的虚拟机和相关游戏，尤其是完美世界竞技平台及其游戏。HCL 使用期间不要启动需要该反作弊驱动的游戏。
2. 备份自己需要的 HCL 工程、设备配置、镜像及 VirtualBox 配置；不要删除项目或虚拟磁盘。HCL 的工程目录可在其设置中查看。
3. 如果只是个别设备失败、诊断虚拟机可以运行，或报错与上面不同，应先看 HCL 和 VirtualBox 日志，不应直接认定是此驱动问题。

## 二、使用启动助手

1. 将压缩包完整解压，保留 `HCL-start.cmd` 和 `HCL-start.ps1` 在同一个文件夹。
2. 确认相关游戏和 HCL 已退出后，在文件资源管理器里双击 `HCL-start.cmd`，按屏幕提示操作，并在 Windows 的管理员授权提示中选择“是”。管理员权限用于临时停止和恢复 `MessageTransfer` 驱动。
3. 助手会尝试查找 HCL。如果未找到，请按提示选择本机的 `H3C Cloud Lab.exe`。再在 HCL 里打开工程、启动设备，检查控制台是否出现命令行提示符。
4. 关闭 HCL 后，助手会尝试恢复原本处于运行状态的 `MessageTransfer` 驱动。它不修改该驱动的开机启动类型。如果驱动原本没有运行，助手不会为了退出 HCL 而主动启动它。

如果助手提示恢复失败，先关闭 HCL 和所有虚拟机。可以重启电脑后检查驱动和游戏是否恢复；但如果该驱动原本是手动启动，重启不一定会自动恢复。若仍未恢复，请在管理员命令提示符执行 `sc.exe start MessageTransfer` 并检查执行结果；无法恢复时请咨询熟悉本机配置的人员。助手只针对这个驱动，不处理所有游戏反作弊程序或其他启动故障。助手脚本不联网，HCL 自身的联网行为不受此说明约束。

## 三、遇到接口缓存错误时：备份并重建缓存

仅当日志显示 COM 接口调用异常，或 VirtualBox 升级后缓存明显过期时，才考虑此步骤。本次安装使用的是 Python 3.8 缓存，其他版本的目录可能不同。操作前应退出 HCL 及其他可能正在使用该缓存的 Python 程序。

1. 打开文件资源管理器，在地址栏输入 `%TEMP%\gen_py` 并回车。
2. 如果存在 `3.8` 文件夹，将它重命名为 `3.8-hcl-backup`；如果这个名字已存在，给备份名加上日期或其他后缀，避免覆盖。**不要删除原目录。** 如果不存在 `3.8`，不要新建空目录充当备份；继续检查实际安装版本和日志。
3. 重新打开 HCL，让它自行生成新的缓存。确认缓存目录重新出现，再尝试创建并启动设备，进入控制台检查命令行。
4. 如果重建后出现新问题，需要回滚时，先完全退出 HCL；把新生成的 `3.8` 目录改名保存为另一个不同的名字，再把第 2 步保留的旧目录改回 `3.8`。不要覆盖或删除任何备份。

仅能打开 HCL 窗口或看到 VirtualBox 已安装，并不能证明设备已正常工作；应分别检查虚拟机启动、HCL 设备运行和控制台命令行。

## 四、其他提示

- 如 HCL 或其他虚拟机正在运行，先保存并关闭，避免助手影响正在进行的工作。
- 驱动冲突通过本机停止前后的对比得到验证；其他同学应结合自己的日志与测试判断。
- 不需要为了使用此助手而关闭 Windows 内存完整性、Hyper-V、WSL 或其他安全功能。不要直接删除驱动、注册表项、虚拟磁盘或整个 HCL 目录。
- 若启动器无法定位 HCL、设备仍创建失败，或驱动无法恢复，应保留错误提示和日志，针对实际错误继续排查。
