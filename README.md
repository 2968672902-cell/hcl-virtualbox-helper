# HCL 设备启动排查与启动助手

这是一份针对 Windows 上 HCL 设备无法启动的排查记录，以及一个临时处理 `MessageTransfer` 驱动冲突的启动助手。**本项目由使用者整理，不是 H3C、Oracle 或完美世界的官方工具。** 同样的报错可能有不同原因，本方法不能保证适用于所有电脑。

## 适用线索与实测结果

在一台 Windows 11、HCL 5.7.1、VirtualBox 6.1.50 的电脑上，遇到了两个问题：

- VirtualBox 启动虚拟机时出现 `supR3HardenedWinReSpawn`、`Error -104` 和 `Error relaunching VirtualBox VM process: 5`。独立诊断虚拟机在 `MessageTransfer` 驱动运行时启动失败，临时停止驱动后能够启动。
- VirtualBox 升级后，HCL 使用的旧 Python COM 接口缓存导致创建设备时接口参数错误。保留旧缓存并重新生成后，设备能够创建。

处理后，S6850 设备虚拟机成功启动，使用者确认控制台出现命令行提示符。分享版助手在该电脑上实测可以打开 HCL，关闭后驱动恢复运行；之后对取消授权和启动超时处理的代码调整及其他电脑上的兼容性尚未实测。

## 使用启动助手

1. 先保存工程并关闭 HCL、其他虚拟机和相关游戏，特别是完美世界竞技平台及其游戏。使用 HCL 期间不要启动需要该驱动的游戏。
2. 下载仓库的完整 ZIP 并解压，确保 `HCL-start.cmd` 和 `HCL-start.ps1` 在同一目录。
3. 在文件资源管理器中双击 `HCL-start.cmd`，按提示操作并允许 Windows 管理员授权。如果未自动找到 HCL，请选择安装目录里的 `H3C Cloud Lab.exe`。
4. 在 HCL 中启动设备并打开控制台，确认设备出现命令行提示符。HCL 使用完毕后正常退出。

助手会尝试暂时停止原本正在运行的 `MessageTransfer` 驱动，并在 HCL 及虚拟机退出后恢复；**不会修改驱动的开机启动类型**。如果驱动原本没有运行，助手不会主动启动它。助手只针对该驱动；游戏进程检查不能覆盖所有游戏，使用前请自行确认相关游戏均已退出。助手本身不联网，HCL 自身的联网行为不受影响。

如提示驱动恢复失败，先关闭 HCL 和所有虚拟机。在管理员命令提示符中执行 `sc.exe start MessageTransfer`，然后用 `sc.exe query MessageTransfer` 检查状态；重启不一定能恢复原本为手动启动的驱动。

## 缓存修复和回滚

仅当日志显示 COM 接口调用异常，或 VirtualBox 升级后缓存明显过期时再考虑此操作；先备份 HCL 工程、设备配置、镜像及 VirtualBox 配置，并关闭 HCL 和可能使用该缓存的其他 Python 程序。

1. 在文件资源管理器的地址栏打开 `%TEMP%\gen_py`。本次案例使用 `3.8` 目录，其他安装的 Python 版本可能不同。
2. 将 `3.8` 重命名为 `3.8-hcl-backup`；若名称已存在，使用不同名称。保留原目录，不要删除或覆盖。
3. 重新启动 HCL，让它生成缓存，再创建并启动设备，打开控制台验证。
4. 若要回滚，先退出 HCL，将新生成的 `3.8` 重命名保存，再把原备份改回 `3.8`。

完整步骤、故障恢复和适用范围见 [使用说明.txt](使用说明.txt)。不需要为使用助手而关闭 Windows 安全功能、Hyper-V 或 WSL，也不要删除驱动或虚拟磁盘。
